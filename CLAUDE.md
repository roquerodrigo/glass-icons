# glass-icons

@AGENTS.md

Browser-only Liquid Glass PWA icon generator. Composes glyphs from sixteen open icon
sets over a self-contained glass SVG background and exports a full PWA asset ZIP.
Everything runs client side; there is no backend. Deployed to GitHub Pages at
`/glass-icons/`. Public repo — see README for the icon sets and their licenses.

## Generated assets (not in git)
`public/icons/` and `public/catalog.json` are gitignored and produced by
`scripts/build-catalog.ts` from the icon-set packages. `npm run dev`/`npm run
build` regenerate them only when missing (the `predev`/`prebuild` hooks pass
`--if-missing`). Run `npm run catalog` to force a full rebuild after changing the
script, the icon-set deps, or the vendored Icons8 set — the `--if-missing` runs
will not pick those changes up.

## Non-obvious constraints
- The UI is built with the [Astryx](https://github.com/meta/astryx) design system
  (`@astryxdesign/core` + `@astryxdesign/theme-neutral`, forced to dark mode in
  `src/main.tsx`). `src/astryx-themes.ts` is generated by `npx astryx theme add`;
  do not edit it by hand. `src/App.css` only holds what is not theme UI: the
  ambient tint that follows the chosen gradient, the device-like preview docks,
  the light/dark icon tiles and the preset swatches. After bumping Astryx, run
  `npx astryx upgrade --from <old version> --apply`.
- The glass background is emitted as plain SVG (superellipse squircle, layered
  gradients, specular/rim light) with **no `backdrop-filter`**, on purpose: that
  keeps the on-screen preview and the rasterized PNG export pixel-identical. Do
  not reach for `backdrop-filter`/CSS glass — it would desync preview and output.
- The editor preview is drawn on `<canvas>` at `devicePixelRatio` through the
  same `drawSvgOnCanvas` path the PNG export uses (`src/editor/IconCanvas.tsx`).
  Keep CSS `filter` off the visible preview: WebKit rasterizes filtered elements
  at 1x, which blurs them on retina screens. The drop shadow is a separate,
  blurred copy behind the icon.
- `vite.config.ts` sets `base: '/glass-icons/'` because the site lives under a
  Pages subpath. Changing it breaks all asset URLs in the deployed build.
- Icons8 Liquid Glass icons are vendored as `.tsx` React components under
  `vendor/icons8-liquid-glass/`, pinned to the hash in that dir's `COMMIT` file
  (upstream ships no npm package). Every other set comes from an npm devDependency:
  the monochrome sets from their own packages, the color sets from
  `@iconify-json/*` collections, and Meteocons from `@meteocons/svg-static`
  (the static build: the Iconify Meteocons are SMIL-animated, and rasterizing
  an animation captures an arbitrary frame).
- `build-catalog.ts` normalizes each glyph: the root `<svg>` presentation
  attributes move onto a wrapping `<g>`, so `stroke` sets keep the
  `currentColor` stroke their upstream markup already carries (the script adds
  none); `fill` sets get `currentColor` fill only when they carry no paint of
  their own; `glass` (Icons8) keeps its baked-in colors and takes the tint;
  `color` sets keep their own palette and only take the glyph opacity. Preserve
  this per-set `mode` handling when touching the script.
- Glyph IDs are namespaced per icon (`id`, `url(#…)` and `href="#…"`) so they
  cannot collide with the composer's own `<defs>`, and Iconify bodies have
  `xlink:href` rewritten to `href`: the composed SVG declares no `xlink`
  namespace, and an unbound prefix makes the whole image fail to load.

## CI / release
GitHub Pages deploy runs on push to `main` (`.github/workflows/deploy.yml`:
lint + `npm run build`, then `deploy-pages`). Branch protection is on, so land
changes through a PR with green CI; merge with **rebase merge only**.
